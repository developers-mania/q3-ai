# Decisions

One line per decision, with the reason. The reason matters more than the choice
when this is reviewed in October.

| Date | Decision | Why | Decided by |
|---|---|---|---|
| 2026-08-05 | Session 03 topic — published default is **Getting Data Ready** | _one sentence, written in the room_ | Session 01 room |
| 2026-08-12 | Corpus converted from **PDF**, not DOCX, with `pdftotext -layout` | Only PDFs were available; all 75 DPA sections survived extraction, so Session 03 still has structure to recover | Facilitator prep |
| 2026-08-12 | Answer matching ignores whitespace and hyphens | The PDF hard-wraps at ~80 columns, so s.56(5) reads "ninety\ndays"; without this a perfect retrieval scores MISS for typographic reasons | Facilitator prep |
| 2026-08-12 | Corpus text is written and checked out as **LF**, enforced by `.gitattributes` | Windows would otherwise write CRLF, changing the bytes and the checksum; scores are unaffected, but a pin that reports CHANGED on every clean Windows clone teaches people to delete the manifest | Facilitator prep |
| 2026-08-17 | **`ai-strategy-2025.txt` re-extracted** with `tools/pdf2corpus.py`; manifest re-pinned. `dpa-2019.txt` deliberately untouched (hash unchanged) | The Strategy is a two-column PDF and `pdftotext -layout` had flattened it into side-by-side lines — 24% of lines spliced the facing column mid-sentence, so the Strategy's own phrase "anchored by three key pillars and supported by four enablers" did not exist in the text and any question about the pillars scored MISS on a perfect retrieval. Re-extraction loses no content (+25 word tokens, no vocabulary dropped) and recovers more structure (29 → 96 section markers) | Facilitator prep |
| 2026-08-17 | Landmark checks in `tools/prepare_corpus.py` are **phrases, not single words**, plus a new column-interleaving check | The old landmarks were `"pillars"` and `"enablers"` — bare words survive any extraction, including a broken one, so the report passed while the corpus was damaged. A landmark must break when the extraction breaks | Facilitator prep |
| 2026-08-19 | Session 02 ingests from **`corpus/`; there is no `raw/` directory** | The Content Pack specifies a `raw/` copy of both sources. A second copy of a frozen, checksum-pinned corpus can drift from the first, and a downstream system reading the stale one is precisely the Layer 1 failure this session teaches. `corpus/` already *is* the artifact as retrieved | Facilitator prep |
| 2026-08-19 | `manifest.json` **extends** `corpus/MANIFEST.sha256` rather than replacing it | The existing pin answers "did the bytes change". The manifest answers "what were they, and where did they come from" — title, publisher, version, retrieval date. A hash tells you *that* something changed; a version tells you what it changed *from*, which is the difference between an alert and a diagnosis | Facilitator prep |
| 2026-08-19 | The **AI Strategy is parsed to document level only**; citation accuracy is scored over the Act's questions and the exclusion is printed | The Strategy is a policy paper: its numbered headings sit in an interleaved contents block, its body numbering is inconsistent, and several "sections" are figures. A Part/Section tree over it would produce citations that look precise and are not. Scoring its questions either way would distort the metric — as hits it flatters, as misses it penalises retrieval for a property of the source | Facilitator prep |
| 2026-08-19 | Retrieval accuracy moved 47% → 53% on the seed set, which the Content Pack predicted would "barely move" | Explained, not ignored: `strip_furniture()` removes 54 lines of running header and page numbers that Session 01 indexed as content. The banner "Data Protection Act (Cap. 411C) Kenya" appeared 26 times *inside* section text, diluting TF-IDF in every chunk that carried it. The move is a Layer 1 effect, not a retrieval improvement | Facilitator prep |
| 2026-08-19 | **Chunk overlap = 100 characters**, chosen by measuring 0/50/100/200/300 | Overlap 0 maximises citation (38%) but leaves retrieval below Session 02; 100 is the smallest value that moves BOTH above Session 02 (73%/31% against 53%/8%); beyond 200 the corpus grows for nothing. The Study Guide predicted overlap would matter less once cutting is semantic — it matters more, because a chunk beginning with its neighbour's tail matches on borrowed text and is then cited to the passage next door | Session 03 room |
| 2026-08-19 | **Redaction policy: narrow.** Well-shaped patterns plus a name rule requiring an introducing title or role | This is a reference corpus of public documents: compliance risk is near zero and content loss is real and measured. The naive two-capitalised-words rule fires 739 times with a 100% false positive rate, 80 of them on "Data Commissioner", and costs 6 points of retrieval and 8 of citation. For a corpus of user records the broad rule would be correct and the content loss an acceptable price. Returns in Session 09 as a threshold decision | Session 03 room |
| 2026-08-19 | Redaction is applied to **chunk text after chunking**, not to the document before it | Node offsets from `src/parse.py` index into the cleaned text, and a substitution changes its length — `[REDACTED_EMAIL]` is 16 characters where `info@kenyalaw.org` was 17. Redacting first shifts every offset after the first hit, so the chunker cuts in the wrong places. It cost exactly one evaluation question and presented as a redaction side-effect rather than the offset bug it was. Still satisfies s.41's timing requirement: nothing reaches the index unredacted | Facilitator prep |
| 2026-08-19 | Stated plainly: **the corpus is not entirely free of personal data** | The precision measurement assumes it is. The narrowed name rule's two remaining hits are real contributors credited in the Strategy's acknowledgements. The Act contains no personal data; the Strategy names people. Recorded because the assumption is load-bearing for the false-positive rate and would otherwise be quietly wrong | Facilitator prep |
